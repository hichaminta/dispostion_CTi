FeodoTracker abuse.ch — Swiss Security Research
Confiance 90
Qu'est-ce que FeodoTracker ?
FeodoTracker est un projet de abuse.ch (organisation suisse à but non lucratif) qui traque en temps réel les serveurs C2 (Command & Control) utilisés par des botnets malware. Un C2 est le serveur depuis lequel un attaquant commande ses machines infectées. FeodoTracker se concentre sur des familles connues comme Emotet, QakBot, TrickBot, Dridex, IcedID, LockBit. Chaque entrée représente une IP confirmée comme hébergeant un C2 actif ou récemment actif.
Endpointhttps://feodotracker.abuse.ch/downloads/ipblocklist.json
MéthodeJSON Feed GET HTTP public — aucune clé API requise
Format reçuArray JSON : ip_address, malware, first_seen, last_seen, status, port
Fréquence MàJMise à jour continue par abuse.ch (plusieurs fois par jour)
IOC produits
IP C2 malware_family status (online/offline) port C2 first_seen / last_seen
  • Téléchargement du feed JSON complet à chaque run (FULL_SYNC)
  • Clé déduplication : (ip_address, malware) — même IP avec 2 malwares = 2 entrées distinctes
  • Sauvegarde atomique tous les 500 items via fichier .tmp (anti-corruption)
  • Lance automatiquement feodotracker_extractor.py après collecte
Tracking MongoDB
earliest_modified · latest_modified · last_sync_success

ThreatFox abuse.ch — Swiss Security Research
Confiance 90
Qu'est-ce que ThreatFox ?
ThreatFox est une plateforme d'abuse.ch dédiée au partage d'IOC (Indicators of Compromise) multi-types. Contrairement à FeodoTracker qui se limite aux C2 IP, ThreatFox couvre IP:port, URLs de payload, hashes de malware et domaines. Les IOC sont soumis par la communauté de chercheurs et portent chacun un score de confiance natif (0–100) et un threat_type (botnet_cc, payload_delivery, payload, etc.). La plateforme sert aussi de référence croisée pour relier des IOC à une campagne ou famille malware.
Endpoint APIhttps://threatfox-api.abuse.ch/api/v1/ (POST JSON)
Endpoint Bulkhttps://threatfox-api.abuse.ch/v2/files/exports/{api_key}/full.json.zip
AuthHeader Auth-Key: THREATFOX_API_KEY (variable d'env)
Phase 1query=get_iocs / days=7 — nouveautés des 7 derniers jours
Phase 2Bulk ZIP JSON (--full) — historique complet décompressé en mémoire
IOC produits
IP:port C2 URL payload Hash MD5/SHA256 confidence native (0-100) threat_type malware_family
  • Bulk ZIP : dict {id: [{data}]} → flatten en liste plate avant sync
  • Déduplication par id unique ThreatFox + mise à jour si l'IOC évolue
  • Sauvegarde intermédiaire tous les 500 items pour éviter la perte de données
  • Le confidence natif (0-100) est transmis directement au module de scoring

MalwareBazaar Community API abuse.ch — Swiss Security Research
Confiance 95
Qu'est-ce que MalwareBazaar ?
MalwareBazaar est un dépôt collaboratif d'échantillons de malware maintenu par abuse.ch. Des analystes du monde entier y soumettent des fichiers malveillants accompagnés de métadonnées : hashes, type de fichier, famille détectée, tags. Chaque entrée représente un fichier malveillant réel avec son empreinte cryptographique (SHA256, SHA1, MD5) — ce sont des IOC de type "hash de fichier" utilisés pour bloquer ou détecter la présence d'un malware sur un système. Le filtre signature != null garantit que seuls les échantillons avec une famille identifiée sont retenus.

AuthHeader Auth-Key: MALWAREBAZAAR_API_KEY

Phase 2Bulk ZIP JSON · fallback CSV public bazaar.abuse.ch/export/csv/full/
Filtre critiqueSeuls les samples avec signature != null sont conservés (malware identifié)
IOC produits
SHA256 MD5 SHA1 file_name file_type (exe, dll, doc…) signature (famille malware) tlsh / ssdeep (fuzzy hash)

  • Mode AFTER : skip les samples first_seen ≤ last_run (tracking de date)
  • Mode BEFORE (--full) : historique complet via Bulk ZIP
  • Tags : union des sets existants + nouveaux tags découverts

Spamhaus — DROP / EDROP / DROPv6 The Spamhaus Project — Organisation internationale à but non lucratif
Confiance 95
Qu'est-ce que Spamhaus ?
Spamhaus est l'une des organisations de sécurité Internet les plus reconnues au monde, fondée en 1998. Elle maintient des listes de blocage d'adresses IP (DNSBL) utilisées par des milliers de fournisseurs email et opérateurs réseau. Les listes DROP (Don't Route Or Peer) référencent des plages d'IP (blocs CIDR) allouées à des organisations criminelles ou abandonnées contrôlées par des spammers, botnets et cybercriminels. EDROP (Extended DROP) complète DROP avec des sous-allocations. DROPv6 couvre les blocs IPv6 malveillants. Ces listes représentent les niveaux d'infrastructure les plus dangereux du net.
Feed DROPhttps://www.spamhaus.org/drop/drop.txt (IPv4 CIDR)
Feed EDROPhttps://www.spamhaus.org/drop/edrop.txt (sous-allocations étendues)
Feed DROPv6https://www.spamhaus.org/drop/dropv6.txt (IPv6 CIDR)
FormatTexte brut : network ; SBL-reference — lignes ; = commentaires
IOC produits
CIDR IPv4 (plage IP) CIDR IPv6 référence SBL (Spamhaus Block List) nom du feed
  • Parsing ligne par ligne : split ; → extraction réseau CIDR + référence SBL
  • Détection auto IPv4 vs IPv6 via ipaddress.ip_network() Python
  • Déduplication : clé (network, feed_name) — même CIDR dans 2 feeds = 2 entrées
  • 3 feeds traités séquentiellement avec gestion d'erreur indépendante par feed
Tracking MongoDB
earliest_modified · latest_modified (timestamps de collecte par run)

OpenPhish OpenPhish — Feed de phishing automatisé
Confiance 70
Qu'est-ce que OpenPhish ?
OpenPhish est un service de détection de phishing entièrement automatisé (pas de validation humaine). Il analyse en continu des URLs suspectes via des crawlers et détecte les pages qui imitent des sites légitimes (banques, réseaux sociaux, services cloud). Le feed public feed.txt contient les URLs détectées récemment sous forme brute, une par ligne. La confiance de 70 reflète l'absence de vérification manuelle — des faux positifs sont possibles, notamment sur des pages temporairement inaccessibles.
Endpointhttps://openphish.com/feed.txt — liste brute d'URLs
MéthodeTexte TXT GET public — aucune auth requise
Mise à jourFeed mis à jour toutes les quelques heures automatiquement
IOC produits
URL phishing
  • Feed brut sans contexte sur la marque visée ni le pays ciblé
  • Déduplication par hash SHA256 de l'URL normalisée
  • Confiance 70 : feed non modéré — à croiser avec d'autres sources phishing
  • Utilisé en complément de PhishTank pour augmenter la couverture

PhishTank OpenDNS / Cisco — Vérification communautaire
Confiance 70
Qu'est-ce que PhishTank ?
PhishTank (géré par Cisco/OpenDNS) est un système de signalement et vérification communautaire de phishing. Des utilisateurs soumettent des URLs suspectes, et d'autres membres de la communauté votent pour confirmer ou infirmer si l'URL est un vrai phishing. Chaque entrée porte un statut verified (validé par vote) et un champ target identifiant la marque imitée (PayPal, Microsoft, Google, banques...). La confiance de 70 reflète la nature communautaire — une URL peut être contestée ou les votes biaisés.
MéthodeJSON Feed téléchargement du dump complet
IOC produits
URL phishing phish_id verified (true/false) target (marque imitée) submission_time
  • Seules les URLs verified=true sont priorisées (validées par votes)
  • Déduplication par phish_id unique assigné à chaque soumission
  • Champ target permet de contextualiser l'attaque (qui est imité)
  • Utile pour les règles de blocage orientées marque (brand protection)

URLHaus abuse.ch — Swiss Security Research
Confiance 80
Qu'est-ce que URLHaus ?
URLHaus est un projet d'abuse.ch spécialisé dans le tracking des URLs utilisées pour distribuer des malwares (et non du phishing au sens strict). Ces URLs hébergent des payloads malveillants : exécutables, scripts PowerShell, documents Office malicieux. Les chercheurs soumettent des URLs qu'ils ont découvertes pendant leurs analyses, avec des tags précisant le type de malware distribué (Emotet, TrickBot, AgentTesla...). Le champ status (online/offline) est mis à jour en temps réel par abuse.ch.
Endpointhttps://urlhaus-api.abuse.ch/v1/urls/recent/
MéthodeJSON Feed — retourne les URLs malware les plus récentes
IOC produits
URL malware (distribution) status (online / offline) threat (malware / phishing) tags (Emotet, TrickBot…) date_added
  • Réactivité très élevée — URLs souvent publiées dans les heures suivant une campagne
  • Le champ status permet de filtrer les URLs encore actives
  • Différent de PhishTank : focus sur distribution malware, pas imitation de marque
  • Déduplication par id URLHaus

CINS Army Stage 2 Security — Collective Intelligence Network Security
Confiance 75
Qu'est-ce que CINS Army ?
CINS (Collective Intelligence Network Security) est un projet de Stage 2 Security qui agrège des données de réputation IP issues de multiples honeypots, systèmes de détection et rapports d'abus. La liste ci-badguys.txt contient des adresses IP ayant été observées dans des activités malveillantes : scans de masse, attaques brute-force SSH, exploitation de vulnérabilités, C2 de botnet. C'est une liste de blocage IP pur, sans métadonnées enrichies — une IP est listée si elle a été signalée par plusieurs sources indépendantes.
Endpointhttps://cinsscore.com/list/ci-badguys.txt
MéthodeTexte TXT GET public — une IP par ligne
IOC produits
IP malveillante
  • Liste minimaliste : IP seulement, pas de contexte sur le type d'activité malveillante
  • Agrégation multi-sources → fiabilité supérieure à une seule source de signalement
  • Déduplication par IP unique
  • Utile en complément de Spamhaus pour les IP non encore dans les listes officielle

NVD — National Vulnerability Database NIST — National Institute of Standards and Technology (USA)
Confiance 100
Qu'est-ce que le NVD ?
Le NVD est la base de données officielle des vulnérabilités informatiques du gouvernement américain, maintenue par le NIST (National Institute of Standards and Technology). C'est la référence mondiale pour les CVE (Common Vulnerabilities and Exposures). Chaque CVE dans le NVD est enrichie d'un score CVSS (Common Vulnerability Scoring System) calculé par des analystes NIST — ce score de 0 à 10 mesure la gravité de la vulnérabilité selon des critères standardisés (accessibilité réseau, complexité d'exploitation, impact confidentialité/intégrité/disponibilité). Le NVD couvre toutes les vulnérabilités CVE publiées, des plus anciennes aux plus récentes, et supporte plusieurs versions CVSS : 2.0, 3.0, 3.1 et 4.0.
Endpointhttps://services.nvd.nist.gov/rest/json/cves/2.0
AuthHeader apiKey: NVD_API_KEY (optionnel — augmente le quota à 50 req/30s)
Pagination500 CVE par page · paramètre startIndex pour itérer sur l'ensemble
IncrémentallastModStartDate / lastModEndDate pour ne collecter que les CVE modifiées depuis le dernier run
IOC / données extraites
cve_id (CVE-YYYY-NNNN) CVSS score (toutes versions) description EN published / lastModified CWE (type de faille) CPE (produits affectés)
  • Backoff exponentiel : 5s, 10s, 15s... sur erreur HTTP (API NVD instable par moments)
  • Extraction de toutes les versions CVSS disponibles pour chaque CVE (multi-version)
  • Sleep 1.5s entre pages pour respecter les limites de l'API NVD
  • Déduplication par cve_id — mise à jour complète si CVE re-scorée ou enrichie
Tracking MongoDB
last_run (date ISO → utilisée comme lastModStartDate au prochain run)

The DFIR Report The DFIR Report — Équipe d'analystes cybersécurité
Confiance 100
Qu'est-ce que The DFIR Report ?
The DFIR Report est un blog tenu par une équipe d'analystes DFIR (Digital Forensics & Incident Response) qui publient des rapports détaillés d'intrusions réelles qu'ils ont analysées. Chaque article décrit une attaque de A à Z : initial access, mouvement latéral, persistance, exfiltration, et se termine par une section IOC (Indicators of Compromise) listant les éléments techniques observés. Ces IOC sont de la plus haute valeur car ils proviennent d'incidents réels confirmés — IPs C2 utilisées, hashes des outils déployés, domaines de staging, CVE exploitées. La collecte utilise d'abord le flux RSS pour détecter les nouveaux articles, puis du scraping HTML pour extraire le contenu complet.
Étape 1 — RSSGET https://thedfirreport.com/feed/ — parse XML pour liste des articles
Étape 2 — ScrapingGET article complet → extraction <div class="entry-content"> via parser DOM maison
Section IOCRegex cherche "Indicators of Compromise" dans le HTML → tronque après la section
Limite par runMax 20 articles par exécution — skip si déjà collecté ET contenu > 1000 chars
IOC produits
IP C2 (observées en incident réel) SHA256 (outils des attaquants) domaines C2 CVE exploitées contexte NLP TTPs MITRE
  • Re-fetch si contenu trop court au 1er essai (article encore en cours de publication)
  • Comptage de <div> pour trouver la fermeture de entry-content sans bibliothèque lourde
  • Snapshot journalier : dfir_report_data_YYYY-MM-DD.json
  • NLP spaCy appliqué ensuite pour extraction des entités dans le texte de l'article
Tracking MongoDB
earliest_modified · latest_modified (dates pubDate RSS des articles)

AlienVault OTX — Open Threat eXchange AT&T Cybersecurity (anciennement AlienVault)
Confiance 75
Qu'est-ce que AlienVault OTX ?
OTX (Open Threat eXchange) est la plus grande plateforme communautaire de partage d'intelligence sur les menaces, avec plus de 100 000 participants mondiaux (chercheurs, entreprises, SOC). Le concept central est le Pulse : un rapport de menace structuré créé par un membre, contenant des IOC typés (IP, URL, hash, domaine, email...) liés à une campagne ou famille malware. Chaque Pulse porte des tags, une description, des références et une liste d'indicateurs. La qualité varie selon l'auteur : un Pulse d'un éditeur réputé vaut une confiance de 90+, un Pulse inconnu peut être du bruit. Confiance globale fixée à 75 en raison de cette hétérogénéité.
LibrairieOTXv2 SDK Python — méthode otx.getall_iter()
AuthClé API OTX_API_KEY dans .env
Phase 1 (AFTER)modified_since=latest_modified → nouveaux pulses depuis le dernier run
Phase 2 (BEFORE)modified_since=None → historique complet (skip si déjà dans l'intervalle connu)
ParallélismeThreadPoolExecutor(max_workers=10) — récupération des indicateurs en parallèle
IOC produits
IP URL domaine Hash (MD5/SHA1/SHA256) email tags du pulse références (articles, rapports)
  • Sauvegarde progressive tous les 5 pulses (SAVE_EVERY=5) pour éviter la perte en cas d'interruption
  • Limite de 40 tâches pendantes max (MAX_PENDING_TASKS=40) pour ne pas saturer la RAM
  • Page de 200 pulses par requête (PAGE_LIMIT=200)
  • Déduplication par pulse_id — mise à jour complète si pulse modifié par son auteur

earliest_modified · latest_modified (dates modified des pulses collectés)

PulseDive PulseDive — Agrégateur de threat intelligence
Confiance 70
Qu'est-ce que PulseDive ?
PulseDive est un agrégateur de threat intelligence qui collecte des IOC depuis de nombreuses sources publiques (feeds, rapports, communauté) et leur attribue un score de réputation (none / low / medium / high / critical). Pour chaque IOC (IP, URL, domaine), PulseDive enrichit l'entrée avec des données de géolocalisation, le type d'activité malveillante observée, les sources qui l'ont signalé et un historique de risque. C'est un outil de corrélation et d'enrichissement plus qu'une source primaire — sa qualité dépend des sources sous-jacentes qu'il agrège.
Endpointhttps://pulsedive.com/api/ (REST JSON)
AuthClé API PULSEDIVE_API_KEY
IOC produits
IP URL domaine score de réputation tags / catégorie sources ayant signalé
  • Agrégateur : la valeur ajoutée est dans le score de réputation consolidé et la corrélation multi-sources
  • Confiance 70 : qualité dépend de la fraîcheur des sources sous-jacentes
  • Déduplication par id PulseDive
  • Complète bien les sources directes pour les domaines et URLs moins connus

Mécanismes Communs à Toutes les Sources

🔄 Tracking MongoDB — Incrémentalité

Chaque source possède un document de tracking dans MongoDB mis à jour après chaque run. Cela évite de re-télécharger l'historique complet à chaque exécution.

  • SourceTracker(source_name) — un document par source dans la collection source_tracking
  • Champs communs : earliest_modified / latest_modified / last_sync_success / last_run
  • Fallback : si MongoDB est indisponible → tracking ignoré, collecte complète sans crash
  • Le tracking permet deux modes : AFTER (nouveautés) et BEFORE (historique)

⚡ Automation — Chaînage Collection → Extraction

Après chaque collecte, le script lance automatiquement l'extracteur correspondant via subprocess.run() pour un pipeline continu sans intervention manuelle.

  • Chaque script collecte déclenche son extracteur : feodotracker_extractor.py, threatfox_extractor.py…
  • L'extracteur est lancé dans le même processus Python avec sys.executable
  • Si l'extracteur est absent : warning loggé mais la collecte est marquée succès
  • Permet un pipeline entièrement automatisé depuis le run_pipeline.py maître

💾 Sauvegarde Atomique — Anti-Corruption

Toutes les sauvegardes JSON utilisent le pattern write-then-rename pour éviter la corruption en cas d'interruption.

  • Écriture dans un fichier .tmp temporaire
  • os.replace(tmp, target) — opération atomique sur le système de fichiers
  • Sauvegarde intermédiaire tous les SAVE_EVERY=500 items
  • Export journalier séparé : source_data_YYYY-MM-DD.json (nouveaux items uniquement)

🔑 Déduplication — Clés par Source

Chaque source définit sa propre clé de déduplication pour éviter les doublons dans le fichier JSON accumulé.

  • FeodoTracker : (ip_address, malware)
  • ThreatFox / URLHaus / PulseDive : id unique de la plateforme
  • MalwareBazaar : sha256_hash
  • NVD : cve_id
  • AlienVault OTX : pulse_id
  • Spamhaus : (network, feed_name)
  • PhishTank : phish_id
  • OpenPhish / CINS : hash ou valeur unique de l'IOC
