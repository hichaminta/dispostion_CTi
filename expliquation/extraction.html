Mécanisme Détaillé d'Extraction des IOCs et CVEs

La Puissance de `BaseExtractor` : Le Moteur Central

Situé dans extraction_ioc_cve/base_extractor.py (729 lignes de code), c'est le coeur du parsing textuel du système. Il transforme n'importe quel dictionnaire JSON ou bloc de texte non structuré en une liste normée d'indicateurs (IP, URL, MD5, CVE).

1. Les Expressions Régulières (Regex)

Regex Extrêmes IPv6 Complexes

Le constructeur de BaseExtractor définit un dictionnaire de regex très strictes pour s'assurer que rien n'échappe à l'extracteur :

self.patterns = {
    # Capture IPv4 standard (ex: 192.168.1.1)
    'ip': r'\b(?:(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.){3}...\b',
    
    # Capture IPv6 (très complexe en regex car compression des zéros avec ::)
    'ipv6': r'\b(?:[a-fA-F0-9]{1,4}:){7}[a-fA-F0-9]{1,4}\b|\b(?:[a-fA-F0-9]{1,4}:){1,7}:|:[:a-fA-F0-9]{1,7}\b',
    
    # Capture les plages CIDR (ex: 10.0.0.0/8)
    'ip_range': r'\b(?:(?:25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.){3}.../(?:[1-2]?[0-9]|3[0-2])\b',
    
    # Capture les hashes avec exactitude (longueur 32, 40, 64)
    'md5': r'\b[a-fA-F0-9]{32}\b',
    'sha256': r'\b[a-fA-F0-9]{64}\b',
    
    # Capture les CVE avec l'année
    'cve': r'CVE-\d{4}-\d{4,}'
}

2. L'Intelligence Anti-Faux Positifs (Whitelisting & Filtres)

Exclusion Systématique

Extraire des noms de domaines dans des textes bruts génère beaucoup de déchets. La classe implémente self.WHITELIST_DOMAINS (contenant google.com, github.com, microsoft.com, 127.0.0.1). Si un indicateur trouve un domaine lié (ex: api.google.com), la fonction récursive is_whitelisted() le supprime des résultats.

De plus, l'algorithme fait la distinction entre un "Domaine" et un "Nom de fichier" qui se ressemblent (ex: malware.exe ressemble à un domaine .exe en regex).

self.INVALID_DOMAIN_EXTENSIONS = {
    '.exe', '.dll', '.zip', '.rar', '.js', '.bin', '.dat', '.tmp', '.json', '.txt'
}
# Logique de rejet :
for ext in self.INVALID_DOMAIN_EXTENSIONS:
    if val_lower.endswith(ext):
        is_filename = True
        break # Ignoré en tant que domaine

3. L'Extraction Sémantique des Noms de Fichiers (Hashes Mapping)

Parsing Sémantique

Une des fonctions les plus avancées est extract_file_hashes_general(text). Parfois, un rapport DFIR texte ressemble à :
"File: trojan.exe
8b1a9953c4611296a827abf8c47804d7".
Le parseur détecte le mot-clé File:, mémorise le nom trojan.exe, et l'associe dans un dictionnaire à chaque hash trouvé sur les lignes suivantes.

# 1. Header detection
header_match = re.match(r'^(?:File|Filename|Fichier):\s*(.+)$', line, re.IGNORECASE)
if header_match:
    current_header_file = header_match.group(1).strip()
    
# Si on a un fichier "actif", on attache le hash
if current_header_file and hash_regex.match(line):
    file_map[line.lower()] = current_header_file

Ensuite, l'attribut ioc['file'] = trojan.exe est injecté dans le JSON final pour le hash donné.

4. L'Enrichissement Natif lors de l'Extraction

Ancrage d'Attributs

Plutôt que d'avoir un "IOC nu", la méthode _extract_attributes(item) aspire toutes les clés intéressantes trouvées à la racine du JSON récupéré de l'API (ex: pays, ports, nom du malware, niveau de confiance de la source), et les ancre directement dans un bloc ioc_enrichment pour CHAQUE indicateur (URL, Hash, IP).

# Résultat d'un IOC typique renvoyé par la pipeline d'extraction :
{
    "type": "hashe",
    "value": "b9c5a... (sha256)",
    "file": "invoice.exe",
    "source": "MalwareBazaar Community API",
    "ioc_enrichment": {
        "file_size": 15042,
        "malware_family": "emotet",
        "tlsh": "T1EF11...",
        "intel_downloads": 405
    }
}

5. La Fusion et Normalisation Intelligente (Merge)

Dédoublonnage JSON

La méthode merge_results prend le vieux fichier JSON et le nouveau, et les fusionne. C'est ici que l'orthographe est normalisée pour l'outil de stockage final (MISP ou Base de données). Par exemple, le type "domain" devient "domaine", et "sha256/md5" devient "hashe".

type_map = {"domain": "domaine", "hash": "hashe", "sha256": "hashe", "md5": "hashe"}

# Si l'IOC existe déjà, on fusionne son enrichissement
if "ioc_enrichment" in new_ioc:
    for ek, ev in new_ioc["ioc_enrichment"].items():
        existing_ioc["ioc_enrichment"][ek] = ev

Cela garantit que le système s'enrichit sans cesse sans jamais dupliquer un IOC, gardant un fichier _extracted.json optimisé et propre.
