Mécanisme Détaillé d'Extraction des IOCs et CVEs

La Puissance de `BaseExtractor` : Le Moteur Central

Le fichier base_extractor.py gère le parsing universel des textes et JSON. Ses expressions régulières (Regex) sont redoutables et identifient avec précision adresses IP, plages CIDR, Hashes (MD5, SHA1, SHA256) et vulnérabilités (CVE).

1. Filtrage et Intelligence Anti-Faux Positifs

Exclusion Systématique Whitelisting Dynamique

Dans l'analyse des domaines, l'extracteur distingue les domaines réels des faux positifs. Des noms de fichiers (malware.exe, script.js) peuvent ressembler à des domaines pour une Regex. L'extracteur vérifie contre un set de INVALID_DOMAIN_EXTENSIONS (.exe, .dll, .js, .sys).

Il maintient également une liste blanche de domaines à ignorer de manière récursive (Microsoft, Google, GitHub, localhost).

2. L'Extraction Sémantique et NLP (Natural Language Processing)

SpaCy Models Entity Recognition

Le système implémente une logique spécifique ultra-avancée pour The DFIR Report. Plutôt que de chercher aveuglément des IPs, il utilise la bibliothèque d'IA SpaCy (en_core_web_sm) pour comprendre le sens grammatical du texte.

Le code extrait les TTPs (Tactics, Techniques & Procedures) en classant le texte en 4 grandes catégories :

  • Commandes: Regex spécifiques cherchant "powershell", "net user", "wmi".
  • Actors: Reconnaissance des groupes de menace via l'entité "ORG" de SpaCy couplée à des mots-clés ("spider", "unc", "ransomhub").
  • Victims: Localisations ou cibles identifiées par les tags SpaCy "GPE" (Géopolitique) et "LOC".
  • Technology: Le tag SpaCy "PRODUCT" repère les logiciels ciblés, complété par une extraction Regex pour capturer la version (ex: Log4j 2.x, Apache 2.4.51).
doc = nlp(clean_text)

3. L'Analyse Contextuelle des Faux Positifs (DNS Resolvers)

Contextual Heuristics

L'extracteur DFIR intègre une logique de filtrage des IP qui élimine intelligemment les résolveurs publics (ex: 8.8.8.8, 1.1.1.1), les IPs de bouclage, privées, multicast, et va même jusqu'à détecter des versions de logiciels déguisées en IP (ex: version "19.0.0.0").

Le filtrage s'appuie également sur le résultat du modèle NLP : les domaines liés à une entité marquée comme "victim" (ex: domaine interne de l'entreprise ciblée) sont mis sur liste blanche dynamique et rejetés de la liste des attaquants.

4. L'Enrichissement Natif par Mapping de Structure

Ancrage d'Attributs JSON

Pour les APIs structurées comme ThreatFox ou MalwareBazaar, le BaseExtractor récupère non seulement l'IOC, mais aspire récursivement toutes les clés adjacentes (tags, type d'arme, niveau de menace) pour les injecter dans un sous-dictionnaire ioc_enrichment propre à chaque IOC.

5. Partitionnement et Format de Sortie Normalisé

Dédoublonnage JSON Routage Intelligent

Les données extraites sont fusionnées (merged) avec l'existant. L'orthographe est normalisée (ex: "domain" devient "domaine"). Les attributs contextuels s'additionnent si l'IOC existait déjà.

Le système route les menaces intelligemment : s'il s'agit d'un article contenant uniquement des CVE sans indicateurs compromis, le rapport est envoyé dans un fichier spécifique (_vuln_extracted.json) formaté pour attaquer directement la phase de corrélation, économisant des appels d'API coûteux.
