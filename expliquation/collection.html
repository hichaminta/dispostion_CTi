Mécanisme Détaillé de Collecte des Sources CTI

Architecture Standard et Résilience

L'auteur de la pipeline a mis en place un "Template" (un socle de code commun) que chaque script de source utilise pour garantir la stabilité du système. Cela passe par deux mécanismes clés : Le suivi MongoDB (Tracking) et la Sauvegarde Atomique.

1. Le Tracking (mongo_tracking.py)

Pour éviter de télécharger les mêmes données en boucle, chaque script appelle un Tracker. S'il n'y a pas de base MongoDB, il crée un fichier JSON local (Fallback). Voici comment MalwareBazaar ou NVD l'utilisent :

def _get_mongo_tracker():
    try:
        from utils.mongo_tracking import SourceTracker
        source_name = os.path.basename(SCRIPT_DIR)
        return SourceTracker(source_name)
    except Exception as e:
        return None

def load_tracking():
    tracker = _get_mongo_tracker()
    return tracker.get_tracking() if tracker else {}

2. La Sauvegarde Atomique (Atomic Save)

Le fait d'écrire de gros fichiers JSON peut prendre du temps. Si le script plante (ou qu'on l'arrête) pendant l'écriture, le fichier JSON est corrompu. Pour l'éviter, le script écrit dans un fichier .tmp avec un UUID unique, puis le renomme de manière quasi-instantanée :

def save_json_atomic(data, filepath=None):
    import uuid
    target_file = filepath if filepath else OUTPUT_JSON
    tmp_file = target_file + "." + uuid.uuid4().hex[:8] + ".tmp"
    
    with open(tmp_file, "w", encoding="utf-8") as f:
        json.dump(data, f, indent=4, ensure_ascii=False)
        
    # Os.replace écrase le fichier cible de manière atomique
    os.replace(tmp_file, target_file)

Détail Source : NVD (National Vulnerability Database)

Pagination Indexée Rate Limit Dynamique Extraction CVSS Différenciée

L'API NVD est très capricieuse et bloque facilement les adresses IP (Rate-Limiting). Le code gère un "backoff exponentiel", c'est-à-dire qu'il attend de plus en plus longtemps entre chaque essai en cas d'erreur.

def fetch_cves(params, retries=5):
    headers = {"apiKey": API_KEY} if API_KEY else {}
    for i in range(retries):
        try:
            r = requests.get(BASE_URL, params=params, headers=headers, timeout=60)
            r.raise_for_status()
            return r.json()
        except Exception as e:
            if i == retries - 1: raise e
            # Attente : 5s, puis 10s, puis 15s
            sleep_time = 5 * (i + 1)
            time.sleep(sleep_time)

Le paramétrage temporel utilise la date exacte UTC du tracking précédent pour ne récupérer que les "Nouveautés" et paginer via startIndex et resultsPerPage.

Détail Source : MalwareBazaar (abuse.ch)

API REST Mode Bulk en Mémoire

MalwareBazaar a deux comportements. Le premier télécharge les 100 derniers malwares via l'API. Le second (mode Bulk) est invoqué si l'argument --full est passé. Il télécharge un énorme fichier ZIP contenant toute la base. Le code extrait ce fichier ZIP directement en mémoire (BytesIO) pour éviter de créer un fichier massif sur le disque de l'ordinateur :

def fetch_bulk_export():
    url_json = "https://mb-api.abuse.ch/v2/files/exports/{api_key}/full.json.zip"
    response = requests.get(url_json, timeout=300)

            data = json.load(f)
            return data.get("data", [])

Parsing Ligne par Ligne Validation IP

Pour les sources fournissant des fichiers "plats" (juste du texte brut), la pipeline doit s'assurer de ne pas injecter des commentaires ou du code cassé dans sa base. Elle utilise le module ipaddress natif de Python.

def is_valid_ip(ip_str):
    try:
        import ipaddress
        ipaddress.ip_address(ip_str)
        return True
    except ValueError:
        return False

# Dans la boucle de lecture :

Détail Source : OTX AlienVault (SDK & Multi-Threading)

Pool de Threads SDK OTXv2

OTX fonctionne par "Pulses" (Rapports). Un Pulse peut contenir des centaines d'indicateurs (IOCs). Récupérer le contenu d'un Pulse prend 1 seconde. S'il y a 500 Pulses, cela prendrait 500 secondes séquentiellement. Le script utilise un ThreadPoolExecutor (10 travailleurs simultanés) pour paralléliser les requêtes réseau et gagner énormément de temps.

L'Automatisation Post-Collecte

À la toute fin du bloc main() de n'importe quel script de collection, on retrouve systématiquement ce bloc qui ordonne au système de déclencher immédiatement le parseur d'Extraction associé, créant ainsi la continuité de la "Pipeline" :

# [AUTOMATION] Extraction directe des IOCs/CVEs après collecte
extraction_dir = os.path.abspath(os.path.join(SCRIPT_DIR, '..', '..', 'extraction_ioc_cve'))
extractor_script = os.path.join(extraction_dir, "nvd_extractor.py")
subprocess.run([sys.executable, extractor_script], cwd=extraction_dir)
