Mécanisme Détaillé de Collecte des Sources CTI

Architecture Standard et Résilience Globale

L'architecture de collecte repose sur un socle commun robuste qui garantit qu'aucune donnée n'est dupliquée et qu'aucune corruption ne se produit lors de l'écriture. Chaque script de collecte hérite de ces mécanismes de base :

1. Le Tracking Intelligent (MongoDB & Fallback JSON)

Chaque source maintient un curseur temporel (timestamp de la dernière collecte). Avant toute requête réseau, le script interroge la base de données de suivi (Tracker) pour reprendre exactement là où il s'est arrêté.

def _get_mongo_tracker():
    try:
        from utils.mongo_tracking import SourceTracker
        source_name = os.path.basename(SCRIPT_DIR)
        return SourceTracker(source_name)
    except Exception as e:
        return None

2. Sauvegarde Atomique (Prévention de Corruption)

Écrire des gigaoctets de données JSON est risqué. Si une coupure survient, le fichier cible est corrompu. La fonction save_json_atomic utilise un fichier temporaire .tmp avec un UUID, puis utilise os.replace() au niveau système pour remplacer instantanément le fichier final.

1. NVD (National Vulnerability Database)

Pagination Indexée Rate Limit Dynamique CVE JSON

L'API NVD impose des limites de requêtes très strictes. Le script utilise un mécanisme de backoff exponentiel (attente de 5s, puis 10s, puis 15s) en cas de blocage IP (Code 403/429).

Il utilise les paramètres de requête pubStartDate et pubEndDate générés dynamiquement par le Tracker, et pagine avec startIndex et resultsPerPage.

2. MalwareBazaar (abuse.ch)

API REST Mode Bulk en Mémoire ZIP Stream

MalwareBazaar fournit des informations sur les malwares récents. Le script supporte un "Mode Bulk" pour récupérer la base complète historique.

Afin de ne pas sature le disque, le code télécharge un fichier ZIP compressé et le décompresse entièrement en mémoire RAM via io.BytesIO pour en extraire le JSON directement.

with zipfile.ZipFile(io.BytesIO(response.content)) as z:
    json_filename = [f for f in z.namelist() if f.endswith('.json')][0]
    with z.open(json_filename) as f:
        data = json.load(f)

3. The DFIR Report

Scraping Web Parsing HTML Format Non-Structuré

Contrairement aux APIs classiques, DFIR Report fournit des rapports de réponse aux incidents (Incident Response) sous forme de longs articles HTML. Le script télécharge la page, extrait le contenu textuel brut du bloc principal (balises <article> ou classes CSS spécifiques) et l'agrège dans un objet JSON.

Il conserve précieusement le bloc "Indicators of Compromise" pour la phase d'extraction NLP ultérieure.

4. ThreatFox (abuse.ch)

Rotation Quotidienne Volumes Massifs

ThreatFox partage d'énormes listes d'IOCs. Pour éviter des fichiers locaux de plusieurs gigaoctets, la stratégie de stockage de cette source crée des fichiers JSON horodatés (ex: threatfox_data_2026-06-18.json). Le script partitionne les données dès la collecte, facilitant la gestion de l'espace disque.

5. CINS Army

Fichier Plat (TXT) Validation d'IP Stricte

CINS Army distribue un simple fichier texte avec une IP par ligne. Le script implémente une validation stricte avec le module ipaddress de Python pour ignorer silencieusement les commentaires (#), les lignes vides et les éventuelles erreurs de formatage.

6. OTX AlienVault

SDK OTXv2 Multi-Threading Avancé

OTX repose sur le concept de "Pulses", qui eux-mêmes contiennent des "Indicators". Une requête est nécessaire par Pulse pour récupérer ses IOCs.

Le script déploie un ThreadPoolExecutor avec 10 travailleurs simultanés pour lancer les requêtes réseau en parallèle, divisant le temps de traitement de l'historique par 10.

with ThreadPoolExecutor(max_workers=10) as executor:
    futures = {}
    for pulse in otx.getall_iter(modified_since=last_date):
        future = executor.submit(otx.get_pulse_indicators, pulse.get("id"))

7. Spamhaus, OpenPhish & FeodoTracker

Liste Noire Dédoublonnage Local

Ces sources proposent de longues listes textuelles ou CSV (Spamhaus DROP/EDROP, URLs de phishing). Le mécanisme de collecte stocke tout dans des structures en mémoire de type set() (Ensembles Python) lors du parsing pour garantir un dédoublonnage mathématiquement parfait avant l'enregistrement local en JSON.

L'Automatisation Post-Collecte (Triggering)

A la toute fin de chaque script, une commande système ordonne le lancement immédiat du script d'Extraction associé via subprocess.run, liant les phases de la pipeline de manière réactive.
