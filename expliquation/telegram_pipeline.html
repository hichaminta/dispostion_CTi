Tracking incrémental — Gap-Based

Chaque canal a son intervalle connu. Les messages dans l'intervalle sont skippés — seuls ceux en dehors (nouveaux ou historiques manquants) sont traités.

[{ "group_name": "Jabaroot DZ", "start_date": "2026-05-05", "earliest_modified": "2026-04-08T10:23:00", "last_run": "2026-06-20T09:15:00" }] # Messages dans [earliest → last_run] → SKIP # Messages hors intervalle → TRAITÉS
Téléchargement Fichiers
  • Limite : 200 MB — flag SKIPPED_TOO_LARGE si dépassé
  • Progress bar temps réel : \r 12.4 MB / 48.0 MB (25.8%)
  • Formats décompressés : .zip .ziip .rar
  • 100 premières lignes de chaque .txt .sql .csv .json .log
  • Encodage BOM auto-détecté : UTF-8 / UTF-16 / UTF-32 / UTF-8-SIG
  • file_sample tronqué à 6 000 chars avant envoi LLM

Fallback Regex — Toujours actif en parallèle
def extract_patterns(text): return { "emails": re.findall(r'[a-zA-Z0-9._%+-]+@...', text), "ips": re.findall(r'\b\d{1,3}\.\d{1,3}...\b', text), "urls": re.findall(r'https?://[^\s<">]+', text), "credentials": re.findall(r'email@...:password\b', text) }
Si des entités Regex sont trouvées → is_leak=true + confidence=70 même sans LLM. Le champ summary indique "No AI analysis available". Les entités peuplent toujours analysis["entities"] dans le record final.

Override Heuristique — Protection Faux Négatifs LLM
process_message() · core/collector.py
archives = leaks confirmées

Les messages hacktivistes sont souvent en arabe avec rhétorique politique. Le LLM les classe comme "propagande politique" (pas une fuite). Mais si un .zip de 200 MB est attaché, c'est presque certainement une fuite réelle.

Extensions qui déclenchent l'override
ARCHIVE_EXTS = ( '.zip', '.ziip', '.rar', '.dbf', '.sql', '.xlsx', '.xls', '.xlsm', '.csv', '.txt', '.log' ) is_archive = file_path.endswith(ARCHIVE_EXTS) # LLM dit non MAIS archive présente if is_archive and not analysis["is_leak"]: analysis["is_leak"] = True analysis["title"] = "Database Dump / Archive Leak" analysis["severity"] = "High" # → record QUAND MÊME sauvegardé
Tableau de décision
LLM ditArchive ?Action
is_leak = falseNonSkip — non sauvegardé
is_leak = falseOui (.zip, .csv...)Override → is_leak = true
is_leak = trueN'importeSauvegardé normalement
Note code PFE : Le code de suppression physique des fichiers faux-négatifs a été commenté volontairement ([MODIFICATION PFE] dans le code) pour éviter les pertes en cas de mauvaise classification — les fichiers restent sur disque.

IntelligenceAgent — Sauvegarde Purifiée
IntelligenceAgent.save_intel() · core/intelligence.py
leaks_intel.json
Règles de filtrage
  • Skip si is_leak = false — double sécurité post-override
  • Skip si extracted_files vide — preuve fichier obligatoire
  • ID : INTEL-{YYYYMMDD}-{ORG[:3].upper()}-{msg_id}
  • Déduplication par intel_id — merge des fichiers si doublon
  • Deux destinations : data/leaks/{canal}/{date}/leaks.json et results/leaks_intel.json
Pourquoi skip les messages sans fichier ?

Les messages-menaces textuels ("on va publier vos données") sans archive sont stockés dans leaks.json du jour mais exclus de leaks_intel.json. Ils seront fusionnés avec l'archive correspondante par le LLM #2 lors de la corrélation.

Format INTEL sauvegardé

PROMPT LLM #2 — Corrélation & Fusion des Incidents du Jour
IntelligenceAgent.process_daily_leaks() · runner_intelligence.py
Corrélation cross-messages

Ce deuxième appel LLM est lancé manuellement ou en tâche planifiée via runner_intelligence.py. Il analyse tous les leaks d'un jour pour un canal et fusionne menaces + archives en incidents consolidés.

Le problème à résoudre — Pattern hacktiviste
📢 Message 51 — Menace textuelle (pas de fichier)
"سنكشف قاعدة بيانات وزارة الداخلية المغربية"
"Nous allons publier la BDD du Ministère de l'Intérieur"
→ save_intel() l'a ignoré (pas de fichier)
📦 Message 53 — Archive publiée
"وزارة الداخلية.zip — 2.3 GB"
800k lignes d'employés, ID national, salaires
→ save_intel() l'a sauvegardé
LLM #2 → fusionne 51+53 → un seul incident "Ministère de l'Intérieur" avec fichier + résumé unifié en français
Données envoyées (prompt_data)

Seuls les champs nécessaires — économie de tokens :

[{ "id": 51, "date": "2026-04-08T09:45:00", "summary": "Menace publication BDD...", "targets": ["Ministère de l'Intérieur"], "severity":"high", "files": [], ← texte seul "is_threat_only": true ← pas de média },{ "id": 53, "date": "2026-04-08T10:02:00", "summary": "Archive ZIP 2.3GB...", "targets": ["وزارة الداخلية"], "files": ["wiz_interieur.zip"], "is_threat_only": false }]
Prompt LLM #2 — Texte complet envoyé
CORRELATION AND MAPPING TASK: Here are the Telegram leaks detected on {date_str} for channel {channel_name}. Your task is to correlate and map these messages into FINAL Intelligence Incidents. RULES: 1. If a message is a threat (تهديد) and another message contains the actual file/archive for the SAME target, you MUST MERGE them into ONE incident. 2. A final incident should ideally have an extracted file. 3. The ONLY case where an incident has no file is if it is a pure threat and NO file was detected that day. 4. Normalize target names: 'CNOPS' == 'CNOPS' 'Ministère de l'Intérieur' == 'وزارة الداخلية' 5. Provide a unified summary in French for merged incidents. DATA: {json.dumps(prompt_data, ensure_ascii=False)} OUTPUT FORMAT (Strict JSON ONLY): { "incidents": [{ "target_organization": ["Target"], "leak_type": "PII/Database/Credentials", "severity": "high", "summary_fr": "Résumé unifié en FR...", "extracted_files": ["path1", "path2"], "original_ids": [51, 53] }] }

Distribution TAXII : Le bundle STIX est poussé vers un serveur TAXII 2.1 (POST /collections/{id}/objects). Les organisations abonnées le récupèrent automatiquement via GET et l'ingèrent dans leur SIEM/EDR.
Règle IDS flag — Indicateur vs Observable
IDS = true → Indicateur STIX
  • IP, domaine, hash de malware
  • Bloqué par sondes IDS/firewall automatiquement
  • Objet STIX : indicator avec pattern
  • Nécessite validation humaine avant activation
IDS = false → Observable STIX
  • Email victime, credential, nom de fichier
  • Contexte uniquement — pas de blocage automatique
  • Objet STIX : observed-data + SCO
  • Alimente enquêtes et notifications
Relation STIX = contexte
  • targets : acteur → victime
  • uses : acteur → technique
  • indicates : indicator → threat-actor
  • Permet graphe de menace complet
